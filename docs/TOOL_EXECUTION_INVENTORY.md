# Tool execution and audit inventory

This inventory records the executable paths verified in the Android source. It is deliberately conservative: a path is counted as covered only when it enters through `ToolRegistry.invoke` or `ToolRegistry.executeUserAction`, reaches the shared `ToolExecutionCoordinator`, derives its capability from an Android grant or an explicit bounded scope, and writes a start event before execution.

## Model-requested tool path

| Action | Entry point | Authorization and audit boundary | Status |
|---|---|---|---|
| List a directory in the selected project | `ProjectDirectoryListToolAdapter` registered in `MainActivity` and exposed through `ToolRegistry` | Model arguments are bound to the app-owned current SAF selection token; relative directory is validated; pending approval is single-use; persisted read grant derives `READ_FILES`; output is limited to 80 entries and 12,000 characters, sanitizes control characters, and never cuts an accepted entry at its output boundary; registry invokes the shared coordinator and Room audit repository | Covered by implementation and policy tests |
| Read a text file from the selected project | `ProjectFileReadToolAdapter` registered in `MainActivity` and exposed through `ToolRegistry` | Model arguments are bound to the app-owned current SAF selection token; exact path is validated; pending approval is single-use; persisted read grant derives `READ_FILES`; registry invokes the shared coordinator and Room audit repository | Covered by implementation and unit tests |
| Create an empty text file in the selected project | `ProjectFileCreateToolAdapter` registered in `MainActivity` and exposed through `ToolRegistry` | Model supplies only a relative path; app binds the current SAF selection token; path and text extension are validated; approval preview shows the exact path and states the file will be empty; persisted write grant derives `WRITE_FILES`; repository refuses collisions; registry invokes the shared coordinator and Room audit repository | Covered by implementation and policy/approval-preview tests |
| Replace the contents of a supported text file | `ProjectFileEditToolAdapter` registered in `MainActivity` and exposed through `ToolRegistry` | Model supplies a relative path and new content only; app binds the active SAF selection; content is capped at 1,200 characters/4 KiB and rejects control/Unicode format characters; approval preview displays the full proposed content; persisted write grant is rechecked; repository creates a backup before replacing the file | Covered by strict model-binding, request-policy, and approval-preview tests; Android SAF/provider runtime remains pending |
| Rename a supported text file in the selected project | `ProjectFileRenameToolAdapter` registered in `MainActivity` and exposed through `ToolRegistry` | Model supplies only the current relative path and new filename; app binds the current SAF selection token; both names are validated; approval preview shows the current path and exact new name; persisted write grant derives `WRITE_FILES`; repository refuses unsupported files and collisions; registry invokes the shared coordinator and Room audit repository | Covered by model-binding, request-policy, and approval-preview tests |
| List backup history for one selected text file | `ProjectFileBackupListToolAdapter` registered in `MainActivity` and exposed through `ToolRegistry` | Model supplies only a relative path; app binds the active SAF selection; exact persisted read grant is rechecked; output contains bounded backup identifiers and timestamps, never backup contents or private storage paths | Covered by strict request-policy tests; Android SAF runtime remains pending |
| Restore one selected app-owned backup | `ProjectFileBackupRestoreToolAdapter` registered in `MainActivity` and exposed through `ToolRegistry` | Model supplies a relative path and backup ID only; app binds selection; ID must match a backup belonging to that exact path; exact persisted write grant is rechecked; destructive approval preview names the target and backup; repository creates a fresh rollback backup before restore | Covered by model-binding and request-policy tests; Android SAF/provider runtime remains pending |

The model receives schemas only. Automatic LiteRT-LM tool execution is disabled; an approval ticket is required before the adapter executes. The directory-list, file-read, empty-file-create, and backup-history-list adapters use the shared `SelectedProjectModelArgumentPolicy`; rename and backup-restore use strict dedicated binders. Each binds the current app-owned selection token; model-supplied selection IDs, URIs, and unknown arguments are rejected. The binders have regression tests for stale/missing selection context, non-string values, and unknown arguments.

| Restore a project backup | `ProjectFilesScreen` confirmed restore flow | Persisted SAF write grant for the exact selected tree URI | `ToolRegistry.executeUserAction` → shared coordinator |
| Rename a project file | `ProjectFilesScreen` confirmed rename dialog | Persisted SAF write grant for the exact selected tree URI | `ToolRegistry.executeUserAction` → shared coordinator |
| Static source scan | `ProjectScanScreen` | Persisted SAF read grant plus explicit ownership/authorization confirmation and in-scan revalidation | `ToolRegistry.executeUserAction` → shared coordinator |
| Read APK manifest metadata | `ApkInspectionScreen` | Read grant for the exact document-picker URI plus explicit ownership/authorization confirmation | `ToolRegistry.executeUserAction` → shared coordinator |
| Export APK report | `ApkInspectionScreen` | Write grant for the exact destination URI | `ToolRegistry.executeUserAction` → shared coordinator |
| Import text model | `ModelRuntimeScreen` model picker | Persisted read grant for the exact selected model URI; grant is released after the import attempt | `ToolRegistry.executeUserAction` → shared coordinator |
| Import vision model | `VisionImagePickerScreen` model picker | Persisted read grant for the exact selected model URI; releases only a grant newly added by this import attempt | `ToolRegistry.executeUserAction` → shared coordinator |

| Apply one approved self-development proposal | `SelfDevelopmentApplyCoordinator.apply` from the proposal review ViewModel | Requires an approved, single-claim proposal for the exact currently selected SAF tree; rechecks persisted read/write grants and source SHA-256 immediately before write; routes through `ToolRegistry.executeUserAction`; creates a backup before write, verifies the resulting SHA-256, and attempts rollback on verification failure | Implemented; end-to-end Android SAF/provider and rollback race tests remain pending |

The project-file editor's backup-history listing is an internal app-private metadata read; it does not read another app's private storage or execute a project action. The project scanner is bounded and read-only. APK inspection reads package metadata only and does not install or execute the APK.

All thirteen user-interface initiated operations listed above now enter through `ToolRegistry.executeUserAction`. The registry owns the shared coordinator and audit repository, so screens cannot accidentally choose a different audit store. Text-model import, vision-model import, and image analysis require a persisted SAF read grant for the exact selected URI before entering the same boundary. Text- and vision-model imports release a temporary persisted read grant after the attempt because the model is copied into app-private storage; both preserve a pre-existing grant. The shared `PersistedUriReadGrantPolicy` is covered by unit tests for both branches. The model-requested `ProjectDirectoryListToolAdapter` and `ProjectFileReadToolAdapter` use the same registry adapter invocation path. The UI operations are not individually registered as model-callable adapters; they remain user-started workflows and are not exposed to the model.

## Gaps that remain open

1. Only project directory listing, text-file reading, empty text-file creation, bounded text-file content replacement, supported text-file renaming, backup-history listing for a selected text file, and restore of a selected app-owned backup are registered for model-requested tool calls. Other operations above are UI workflows using `executeUserAction`; they are not exposed as model-callable adapters.
2. Regression tests cover the catalogued user actions for missing grants, failed start audit, cancellation, operation failure, and successful completion. Screen-level Android SAF interaction and URI revocation races still require platform/device validation.
3. Audit details intentionally avoid recording file contents and sensitive argument values. The audit screen is an operation history, not a full device activity monitor.
4. Dynamic/network assessment adapters, remediation execution, remote execution, microphone capture, and device-wide controls are not implemented and must remain unavailable until separately designed and authorized.

## Completion rule

Keep these two roadmap items complete based on the current registry and regression-test evidence. Reopen them if a new executable action bypasses `ToolRegistry`/`executeUserAction`, or if an adapter is added without per-action authorization and audit tests. A successful unit-test CI run does not establish target-device compatibility or prove Android SAF behavior on a phone.


## Review performed 2026-11-22

A source-level pass over all 114 Kotlin files under `app/src/main/java` found the UI entry points for `executeUserAction` in the APK inspection, model import, project file, project scan, self-development apply, and vision flows. Model-callable adapters derive capabilities from the exact active SAF selection and persisted URI grant; `ToolRegistry.invoke` re-derives those grants immediately before execution. Permission lookup exceptions fail closed to an empty grant set. This is a source audit, not a device test; SAF revocation races and provider behavior remain subject to target-device validation.
